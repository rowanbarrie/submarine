## 🛠️ Code Modification Protocols (Mandatory)

To minimize manual developer copy-pasting, syntax merging, and patch execution faults, AI assistants **MUST** deliver edits strictly using these two pathways:

### 1. Large Updates via Full File Overwrites (Default)
For multi-line additions, structural refactors, or script additions, always provide complete file replacements using standard bash heredocs (e.g., using cat with EOF delimiters).

### 2. Single Target In-Line Edits via sed
For isolated configuration updates or targeted modifications, provide clean Stream Editor commands with strict regex constraints (e.g., sed -i 's/OLD/NEW/g' filename).

## 🚢 Architectural Core Guardrails

When modifying the workspace, ensure your generated payloads comply with these hard constraints:

* **Pure Float Telemetry**: The application relies on continuous Euclidean geometry vectors mapping an absolute 800x800 coordinate layout. Do not introduce integer division or grid cell snap layers.
* **Network Weight Cap**: Client-side delivery must remain under a total weight asset ceiling of 10KB. Avoid external asset frameworks, engines, or design systems. Use native inline styling loops and semantic JavaScript.
* **Network Interlocks**: Socket initialization lines must remain forced to native WebSockets (`{ transports: ['websocket'] }`) to mitigate mobile carrier long-polling overheads.
* **State Tokens**: Targeted adjustments trigger mandatory server-side state token invalidations (`expectedToken`). Weapon payloads will fail server evaluation metrics if an event lacks compliant validation markers generated by the timing slider.
